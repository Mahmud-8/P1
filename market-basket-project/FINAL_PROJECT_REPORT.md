# Final Project Report

## Project Title

Market Basket Analysis and Association Rule Mining

Course: Data Mining (AIE323)

## 1. Project Overview

This project analyzes grocery transaction data to discover products that are often bought together. It uses association rule mining to generate rules such as:

```text
whole milk, yogurt -> sausage
```

The project also includes a rule-based recommendation engine. When a user selects items already in a basket, the system searches the mined rules and recommends the top related products ranked by lift.

The final result is an interactive Streamlit dashboard with:

- Rule Explorer
- Product Recommender
- Network Graph
- Analysis tab
- Dynamic support, confidence, and lift sliders

## 2. Project Objectives

The main objectives are:

- Clean and prepare transactional grocery data.
- Convert transactions into a binary basket matrix.
- Perform exploratory data analysis.
- Analyze product co-occurrence.
- Compute statistical relationship metrics such as lift, chi-squared, and Jaccard similarity.
- Segment baskets using simple clustering.
- Mine frequent itemsets using Apriori and FP-Growth.
- Generate association rules with support, confidence, lift, leverage, and conviction.
- Compare Apriori and FP-Growth performance.
- Build a product recommendation system.
- Build a Streamlit dashboard for interactive exploration.

## 6. Data Cleaning And Preprocessing

The preprocessing code is in:

```text
src/preprocessing.py
```

The cleaning steps are:

- Check that the required columns exist.
- Remove rows with missing member number, date, or item description.
- Convert dates into datetime format.
- Clean product names by converting them to lowercase and removing extra spaces.
- Remove duplicate item records inside the same transaction.
- Create a transaction ID from member number and date.
- If quantity columns exist, remove non-positive quantities.
- If invoice columns exist, remove cancelled invoices.
- Convert the cleaned transactions into a binary basket matrix.
- Remove rare items using minimum frequency filtering.

The basket matrix has:

- Rows = transactions
- Columns = products
- Values = `True` or `False`

Example:

| Transaction | whole milk | yogurt | sausage |
|---|---:|---:|---:|
| 1000_2014-01-01 | True | True | False |
| 1001_2014-01-01 | False | True | True |

## 8. Co-occurrence And Statistical Analysis

Generated files:

For top product pairs, the project computes:

| Metric | Meaning |
|---|---|
| Co-occurrences | Number of baskets containing both products |
| Lift | Strength of association compared with random chance |
| Jaccard similarity | Overlap between two product purchase sets |
| Chi-squared | Statistical dependency between two products |

## 10. Association Rule Mining

The mining code is in:

```text
src/models.py
```

The project uses `mlxtend` to implement:

- Apriori
- FP-Growth

The project compares both algorithms at these support thresholds:

```text
0.01, 0.02, 0.05
```

The comparison is saved in:

```text
outputs/algorithm_comparison.csv
outputs/mining_report.md
```

Association rules include these metrics:

| Metric | Description |
|---|---|
| Support | How often the full itemset appears in all transactions |
| Confidence | How often the consequent appears when the antecedent appears |
| Lift | How much stronger the rule is than random chance |
| Leverage | Difference between observed and expected co-occurrence |
| Conviction | Directional rule strength |

## 11. Important Threshold Note

The assignment asks to filter actionable rules using:

```text
confidence > 0.5
lift > 1.2
```

For this dataset and transaction definition, the strict threshold produces zero rules. This is not a code error. The grocery baskets are sparse and small, so product relationships have low confidence.

To keep the dashboard useful, the project saves two rule outputs:

| File | Purpose |
|---|---|
| `outputs/rules_actionable.csv` | Strict audit output using confidence >= 0.50 and lift >= 1.20 |
| `outputs/rules.csv` | Exploratory dashboard output using confidence >= 0.05 and lift >= 1.20 |

The strict result is documented in:

```text
outputs/mining_report.md
```

## 12. Recommendation Engine

The recommendation code is in:

```text
src/recommend.py
```

The recommender works as follows:

1. User selects one or more basket items.
2. The system checks mined association rules.
3. Rules are matched against the selected basket.
4. Full antecedent matches are prioritized over partial matches.
5. Candidate recommendation items already in the basket are removed.
6. Recommendations are ranked by lift.
7. Confidence and support are used as tie-breakers.

Example:

Input basket:

```text
whole milk, yogurt
```

Possible output:

```text
sausage
```

Matched rule:

```text
whole milk, yogurt -> sausage
```

The recommender also handles edge cases:

- Empty basket
- Unknown product
- No matching rules
- Multi-item antecedents
- Partial antecedent matches

## 20. Limitations

- The dataset has small baskets, so strict confidence thresholds produce no actionable rules.
- Product categories are inferred from keywords, not from official category labels.
- Recommendations are rule-based, not personalized by customer history.
- The dashboard depends on pre-generated output files from `scripts/run_analysis.py`.
